# 심층 사례(Case Study) 페이지 브리프

작성: 2026-11-25 · 대상 사례: DMEC 신사옥 / 힐스테이트 시화호 라군 인테라스
이 문서는 **사이트 반영 전 브리프**입니다. `docs/`는 빌드에 포함되지 않습니다. 사이트 반영은 이 문서를 읽고 `content/`·`build/`에서 진행합니다.

## 0. 이 문서를 받은 세션이 할 일

1. 저장소 `CLAUDE.md`를 먼저 읽고 `git pull` 후 작업한다 (Pages CMS가 `main`에 직접 커밋한다).
2. 아래 §1 방향과 §3 공통 구조에 따라 **프로젝트 페이지 안에 "심층 사례" 구성**을 설계한다. 기존 프로젝트 6건 구조(`content/projects/*.md`)와 충돌하지 않게 한다.
3. §4, §5의 문구와 사실표를 그대로 쓰되, **[확인 필요]** 표시는 채우지 말고 `[입력]` 형태로 두거나 노출하지 않는다.
4. 이미지는 `docs/case-studies/images/`의 후보 중 선별해 `img/projects/…`로 옮기고, 원본이 아닌 웹용(긴 변 2200px 이하)만 쓴다.
5. KO/EN 둘 다 작성한다. 영문은 `en:` 블록 규칙을 따른다.
6. 6건의 기존 프로젝트 페이지 중 §6에 적은 불일치는 **이번 작업 범위에서 수정하지 않고** 목록으로만 보고한다 (June가 나중에 수정).

## 1. 방향 (June·대표님 합의 + 이번 대화 결정)

- 독자: **부동산 업계**(시행·신탁·시공·분양). 작품 감상보다 **입지 분석, 상품 차별화, 사업 리스크 관리(심의·예산·유지관리), 실행력**을 본다.
- 톤: 명확하고 단정하게. 감상적 수식 금지. 확인한 사실만 쓴다.
- 라벨: 두 사례 모두 **"STANDS 프로젝트"**로 표기한다 (수행 범위: 심의·제작·설치 전체, June 확인).
- 일정은 **연도만** 표기한다. 심의는 모두 통과했고 설치까지 완료된 프로젝트다.
- 금액은 **총 예산만** 표기하고 실제 진행 금액·작품별 금액은 쓰지 않는다.
- 사진 출처, 장소, 연도를 사례마다 적는다.

## 3. 공통 구조 (매물 상세처럼 항목·순서 고정)

1. **헤더**: 라벨, 작품명, 작가, 장소, 연도, 용도
2. **대표 이미지 1장**
3. **개요 표**: 위치, 용도, 규모(연면적·층수), 건축주, 연도, 작품 규격·재료, 범위, 총 예산
4. **사이트 분석**: 위치와 경관 조건, 동선과 시점, 이격
5. **큐레이션 근거**: 입지 조건 → 작가·작품 대응
6. **작품 사양**: 규격, 재료, 마감, 조명
7. **결과**: 설치 사진(주·야 구분, 근경·원경)
8. **프로세스·수행 범위**: 심의·제작·설치와 인계
9. 이미지 하단: 출처·연도 캡션

프로젝트 목록·지도 보기와의 연결(건축미술 맵)은 별도 작업이다. 이 구조의 개요 표 항목을 맵 상세에도 그대로 쓰도록 필드명을 맞춘다.

### 큐레이션 근거

- 작가 의도: 기하학적 직선 단위가 모여 결정체가 되고, 작품은 건물 쪽으로 강하게 상승하며 비상의 출발점을 상징한다. 233개 물방울 형상은 결정을 뜻한다. [사실] pptx
